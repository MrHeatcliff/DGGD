# Reproduce PACS visualizations

Install `requirements-domain-gen.lock.txt` and `requirements-visualization.txt`. Restore the recorded final checkpoint paths and PACS dataset first. ERM feature caches are generated by `scripts/representation/analyze.py`; CORAL/MMD native FP32 caches are generated by this visualization script. No checkpoint reselection or retraining occurs.

```bash
OMP_NUM_THREADS=4 OPENBLAS_NUM_THREADS=4 MKL_NUM_THREADS=4 \
  .venv/bin/python scripts/visualization/pacs.py
OMP_NUM_THREADS=4 OPENBLAS_NUM_THREADS=4 MKL_NUM_THREADS=4 \
  .venv/bin/python scripts/visualization/compare.py
```

Use an authorized GPU allocation. The initial run used a single overlapping step within the existing four-GPU training allocation, without requesting additional GPUs. `pacs.py` accepts no credentials and blocks Internet socket connections; pretrained weights must already be cached. Completed per-checkpoint figures are resumable via metrics.json markers. To regenerate changed plot styles, archive/remove the relevant published case folder before rerunning; cached features stay in outputs/.

The source-only PCA affine plane and original classifier weights are saved in plane.npz, while points.csv stores the displayed images and coordinates. The comparison script verifies the same sample identities across methods and recomputes every exported slice prediction. The script also checks that inverse-PCA plus original classifier equals the analytical 2-D slice equation. Native CORAL/MMD checkpoint accuracy must match the recorded final result before export.

PCA and t-SNE are fit independently across checkpoints. These plots describe fixed final representations, not learning trajectories. Figures use seed 100 by predeclared convention; benchmark accuracy charts use all three final seeds. Only complete method/backbone configurations are published as final.
